# Git Workflow

Рабочий процесс для этого репозитория. Все агенты обязаны следовать ему при коммитах и работе с ветками.

## Общие правила

- Работаем только в ветках. `main` всегда остаётся стабильным и готовым к демонстрации.
- Никогда не коммитим в `main` напрямую.
- Push на GitHub — только по явному запросу пользователя (репозиторий выкладывается вручную).
- Никаких деструктивных операций без явного разрешения: `reset --hard`, `clean -fd`, `branch -D`, force-push.

## Модель веток

- `main` — стабильная ветка, только результат готовых задач.
- Ветки задач от `main`:
  - `feat/...` — новая функциональность (например `feat/backend-api`);
  - `fix/...` — исправление бага;
  - `docs/...` — документация;
  - `chore/...` — служебные изменения (настройка репо, зависимости).
- Имена веток — латиницей, kebab-case (git/URL не дружат с кириллицей).

## Этапы задачи

Каждая задача выполняется по цепочке: разведка → план → реализация → проверка.

1. Создай ветку от `main`: `git checkout main` + `git checkout -b <branch>`.
2. Выполняй задачу этапами — один этап = один осмысленный коммит.
3. Перед коммитом:
   - `git status` и `git diff` — убедись, что запланировано только нужное;
   - сборка проходит (`dotnet build` / `npm run lint` + `npm run typecheck`);
   - нет секретов и `.env` файлов в staging;
   - не попали `bin/`, `obj/`, `node_modules/`.
4. Коммить только проверенное и только нужные файлы.
5. Когда задача завершена — открой PR (merge в `main`) с человеческим описанием на русском. Слитие — ревью, затем merge.

## Формат коммитов

Сообщения — на русском, Conventional Commits:

```
тип(область): краткое описание в повелительном наклонении
```

- `feat(server): добавлен эндпоинт /api/chat со SSE-стримингом`
- `feat(web): хук useChat для стриминга ответов`
- `fix(server): корректная обработка таймаута OpenRouter`
- `docs: API-контракт для фронтенда`
- `chore: базовая настройка репозитория`

Тип: `feat`, `fix`, `docs`, `chore`, `style`, `test`, `refactor`, `perf`.
Область: `server`, `web`, `root` и т.п.

Один коммит на всё задание (`done`) — красный флаг. Коммиты должны быть логическими шагами, каждый из которых оставляет проект в собранном состоянии.

## Правила при работе агента

- Агент коммитит сам только если пользователь явно сказал «коммить по ходу / используй gitworkflow». В остальных случаях — показывает дифф и ждёт.
- Не merge свою ветку молча: сначала проверка (reviewer/verifier), потом merge.
- Если коммит зафейлился из-за хуков — исправь и сделай новый коммит, не правь предыдущий через amend без запроса.
