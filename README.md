Одностраничный веб-чат с языковой моделью через [OpenRouter](https://openrouter.ai).
Пишете сообщение — модель отвечает потоково, слово за словом. Ключ OpenRouter живёт
только на сервере и не попадает в браузер (это можно проверить вкладкой Network).

Модели — только бесплатные (`:free`), набор задаётся белым списком на сервере.

---

## 🚀 Быстрый старт

### Требования

- .NET 10 SDK
- Node.js ≥ 20.19 (требование Vite 8)
- Ключ OpenRouter (https://openrouter.ai/keys)

### 1. Ключ

Сервер читает ключ из переменной окружения `OPENROUTER_API_KEY` — в конфиги, бандл или
git он не попадает. Установите перед запуском:

```bash
# Windows (PowerShell)
$env:OPENROUTER_API_KEY = "sk-or-v1-..."

# macOS / Linux
export OPENROUTER_API_KEY="sk-or-v1-..."
```

### 2. Сервер

```bash
dotnet run --project server
```

Поднимется на `http://localhost:5080` и ответит на `/api/health`.

### 3. Клиент

Во втором терминале:

```bash
cd client
npm install
npm run dev
```

Откройте `http://localhost:5173` — чат готов. Vite проксирует `/api` на `localhost:5080`.

### 4. Или всё сразу через Docker

```bash
cp .env.example .env   # и впишите OPENROUTER_API_KEY
docker compose up --build
```

Клиент — на `http://localhost:8080` (nginx раздаёт SPA и проксирует `/api` с
`proxy_buffering off` для SSE).

## 🧱 Структура репозитория

```
server/   ASP.NET Core minimal API — прокси к OpenRouter (ключ здесь, не в браузере)
client/   React + TS + Vite — сам чат
├── Dockerfile + nginx.conf   продакшен-сборка клиента
API.md    контракт бэкенда (эндпоинты, формат ошибок, примеры curl)
```

Прокси-путь стриминга: клиент → `POST /api/chat` (SSE) → OpenRouter. Сервер
нормализует события OpenRouter в три вида: `delta` (фрагмент текста), `done`
(завершение + usage токенов), `error` (тип + понятное сообщение).

## 💡 Ключевые решения и почему именно так

1. **Ключ — только на сервере, поэтому прокси на ASP.NET Core.** Требование из ТЗ:
   ключ не должен попасть в браузер даже во вкладке Network. ASP.NET Core — мой
   основной бэкенд-стек, плюс это «родной» бэк для выбранного фронта: minimal API,
   встроенные HttpClient и System.Text.Json, один проект без ORM/слоёв. Фронт
   общается только со своим бэкендом, а тот уже ходит в OpenRouter с авторизацией.

2. **История переживает перезагрузку — localStorage вместо серверной БД.** Серверное
   хранение истории означало бы регистрацию и авторизацию пользователей — это уже
   другой уровень работы с приложением, не укладывающийся в задачу. Поэтому история
   живёт на клиенте: беседа не теряется при перезагрузке страницы и переключении
   вкладок, сервер остаётся stateless, в браузере нет ничего секретного для хранения.
   Ограничение — 100 последних сообщений, привязанных к браузеру. **Если бы был ещё
   день — обязательно добавил бы регистрацию, авторизацию и хранение истории на
   сервере** (см. «Что дальше»).

3. **Вся валидация — на бэкенде.** Фронту не доверяется вообще: роли сообщений,
   длина текста, лимит сообщений и — главное — модель проверяются сервером.
   Дополнительно модели ограничены белым списком из 20 `:free`-моделей
   (`appsettings.json`), так что даже если подменить `model` в запросе, платная
   модель до OpenRouter не долетит: сервер ответит `400 model_not_allowed`.

4. **Отмена генерации — клиентский `AbortController` + проброс `CancellationToken`.**
   «Стоп» обрывает чтение потока браузером и параллельно отменяет запрос к OpenRouter
   на сервере. Уже полученный кусок ответа не выбрасывается — остаётся в истории и
   помечается. То же самое делает Esc; вне генерации Esc выходит из режима правки
   сообщения. Если за время стрима не успело прийти ни одного фрагмента, показывается
   заглушка, а не пустой пузырь.

5. **Пушбек по ТЗ про обводку фокуса.** Задача просит *убрать* стандартную
   браузерную обводку — но это прямо конфликтует с её же требованием доступности
   («интерфейсом можно полноценно пользоваться с клавиатуры»). Убирать фокус-аутлайн
   полностью мы не стали: **видимый фокус нужен, чтобы Tab не превращался в лотерею.**
   Вместо системной разносортной голубой обводки — единая кастомная фиолетовая
   `:focus-visible`: фокус виден, выглядит одинаково во всех браузерах, а щёлкать
   мышью можно без мигающих рамок.

6. **Единый контракт ошибок.** Бэк отдаёт `{ type, message }` и маппит типичные
   исходы OpenRouter: 402/429 → `quota_limit`, таймаут → `timeout`, обрыв сети →
   `network`, неверный ключ → `auth`. Фронт рисует понятный баннер с иконкой, а не
   вечный спиннер. Плюс автоматический health-poll: если сервер упал и вернулся,
   баннер «Сервер недоступен» снимается сам, без перезагрузки.

7. **Docker — как стандарт поставки.** `docker compose up` поднимает весь стек:
   сервер (хост `:5080` → контейнер `:8080`) и клиент на nginx (хост `:8080` →
   контейнер `:80`) с готовым проксированием `/api` и `proxy_buffering off` для SSE.
   Это сегодняшняя норма для запуска «из коробки».

8. **Редактирование сообщения с переотправкой — для UX.** Рядом со своим сообщением
   можно нажать «изменить»: правка текста и повторная отправка, история ниже точки
   правки перегенерируется. Знакомая механика мессенджеров, которая заметно проще
   «просто начни диалог заново».

9. **Минимум зависимостей.** Фронт — react, react-markdown + remark-gfm (markdown в
   ответах). Сервер — только встроенные библиотеки .NET.

## 🛠 Проблемы, с которыми столкнулись

- **OpenRouter недоступен из РФ: ограничения провайдера / гео-блокировка.** На этапе
  разработки соединение с API OpenRouter не устанавливалось из-за ограничений на
  территории РФ. Решение — поддержка исходящего прокси прямо в проекте
  (`OPENROUTER_USE_PROXY` + `OPENROUTER_PROXY_URL`, см. конфигурацию ниже): сервер
  ходит в OpenRouter через любой HTTP/SOCKS-прокси за пределами РФ, остальной стек
  менять не пришлось. Прокси включается только явно и по умолчанию выключен.

- **Ссылка на API без завершающего слеша.** `BaseUrl` без `/` в конце (например,
  `https://openrouter.ai/api/v1`) ломал склейку пути: `v1` отбрасывался и запросы
  не улетали. Решение — нормализация базового URL в `server/Program.cs`
  (`TrimEnd('/') + "/"`), теперь относительный путь `chat/completions` резолвится
  от `.../v1/` при любом введённом значении.

## 🔭 Что бы я сделал дальше, будь ещё день

- **Несколько бесед** с сайдбаром (надстройка над localStorage или IndexedDB) —
  сейчас есть один диалог и кнопка «Новый чат».
- **Регистрация, авторизация и хранение истории на сервере** (SQLite) — следующая
  ступень после localStorage, чтобы история была на всех устройствах. Раз история на
  всех устройствах невозможна без пользователей — с авторизации и начнём.
- **Поддержка других провайдеров моделей**, например Groq — единый слой-клиент перед
  провайдерами (OpenRouter, Groq, локальные), чтобы переключать источник моделей в
  настройках, а не менять прокси под каждого.
- **Подсветка кода** в markdown (shiki / rehype-pretty-code) — сейчас код в ответах
  уже в отдельных блоках, но без подсветки синтаксиса.
- **Умный контекст**: суммаризация или обрезка хвоста диалога, чтобы длинные беседы
  не съедали лимит в 50 сообщений на запрос.
- **Retry с backoff на 429** и предложение «попробовать другую модель» прямо в баннере.
- **Тесты**: интеграционные на SSE-контракт (сервер), компонентные для формы и
  парсера SSE (фронт, Vitest + React Testing Library). Сейчас проверка ручная.
- **i18n/EN-переключатель**: интерфейс только на русском.
- **Светлая тема**: тёмная выбрана основной, на перспективу — переключатель на светлую.
- **Рефакторинг бэкенда**: сейчас сервер — один проект на минималках; при наличии
  времени разнёс бы его на отдельные файлы и слои (эндпоинты, валидация, клиент
  провайдера, маппинг ошибок), чтобы структура читалась и расширялась проще.

## ⚙️ Конфигурация сервера

| Переменная окружения | Назначение |
|---|---|
| `OPENROUTER_API_KEY` | Ключ OpenRouter. Обязателен. Никогда не в git и не в браузере. |
| `OPENROUTER_MODEL`   | Модель по умолчанию (переопределяет конфиг). |
| `OPENROUTER_BASE_URL`| Базовый URL OpenRouter (по умолчанию `https://openrouter.ai/api/v1`). |
| `OPENROUTER_USE_PROXY`, `OPENROUTER_PROXY_URL` | Исходящий прокси для OpenRouter, если он недоступен напрямую. |

Полный контракт API — в [API.md](API.md).

## ⚠️ Известные ограничения

- История ограничена 100 последними сообщениями и привязана к браузеру/профилю.
- Free-модели периодически упираются в лимиты — показывается понятное сообщение,
  стрим можно повторить или сменить модель.
- Отмена генерации разрывает текущий запрос; «продолжить с места остановки» не реализовано.
